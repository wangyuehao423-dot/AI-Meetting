# Skill：follow-up-decision（追问决策规则）

## 一、这个 Skill 是做什么的

给大模型提供"要不要追问、按什么口径追问"的规则。
决策本身是**纯代码**（`FollowUpDecisionService.decide`）根据分数段选链，
大模型只负责按选定的口径**产出追问正文**。

调用入口：`InterviewAiFacade.generateFollowUpText(...)`
执行载体：LiteFlow 追问链 `followUpBasicChain` / `followUpNormalChain` / `followUpDeepChain`
链路节点：`loadQuestionContext` → 分数段生成节点 → `persistFollowUp`

## 二、分数 → 策略映射（由代码决定，模型不得自行改判）

| 分数 | 链名 | 等级（level） | 追问目标（objective） |
| --- | --- | --- | --- |
| `< 60` | followUpBasicChain | 基础追问 | 补齐概念定义、核心原理和最小可运行例子 |
| `60 ~ 79` | followUpNormalChain | 常规追问 | 补充实现细节、排障过程和验证方式 |
| `>= 80` | followUpDeepChain | 深度追问 | 验证边界条件、性能取舍、故障恢复与架构决策 |
| NONE（预留） | — | — | 免追问，直接进入下一题 |

> `NONE` 分支已在 `FollowUpGenerationService.generate` 中预留：
> 一旦决策返回 `NONE`，直接推进 `ASK_COMPLETED` 并预生成下一题，不调用大模型。

## 三、三个分数段的追问口径

### 1. 基础追问（分数 < 60）

- 先确认概念定义 → 再拆核心原理 → 最后要一个最小可运行例子。
- 语气耐心、逐步解释，**不预设候选人已经掌握**。
- 不追问架构取舍，先把地基问清楚。

### 2. 常规追问（分数 60 ~ 79）

- 补实现细节、排障过程和验证方式。
- 默认候选人已掌握基础，追问**不放水，也别突然拔高**。
- 重点问"你具体怎么做的""出问题怎么排查的"。

### 3. 深度追问（分数 >= 80）

- 挖边界条件、性能取舍、故障恢复与架构决策。
- 追问要有**阶梯感**，从候选人的回答逐层加深，而不是直接抛一个更大的新问题。
- 允许问"如果规模扩大 100 倍会怎样""这个方案在什么情况下会失效"。

## 四、输出契约（必须严格遵守）

**只返回追问正文的纯文本，不要返回 JSON，不要附加解释、编号或前缀。**

- 中文，一句话到两句话，是一个可以直接念给候选人听的问题。
- 必须以候选人的**实际作答内容**为切入点，围绕**原题**发问。

## 五、追问规则

1. **围绕原题**：追问是原题的延伸，不能变成一道全新的、与作答无关的题。
2. **针对答面**：候选人答了什么就追什么；答错的地方追概念，答对的地方追边界。
3. **一问一追**：一次只追问一个方向，不要在一句话里塞三四个问题。
4. **不重复**：不要把原题换几个字再问一遍。
5. **不泄露答案**：追问里不能包含正确答案或评分标准。
6. **不越级**：严格按照上表分数段的口径来，低分不要问架构，高分不要问"什么是线程"。

## 六、禁止事项

- 不要输出"追问：""问题："等前缀。
- 不要输出 JSON、Markdown 或任何结构化包裹。
- 不要编造候选人没提过的经历、项目或技术栈。
- 不要评价候选人的表现（评语属于 `interview-scoring` Skill 的职责）。
