# Skill：interview-scoring（评分规则）

## 一、这个 Skill 是做什么的

给大模型提供"回答打分"的统一标准，让同一道题、同一份回答在不同时间、
不同并发请求下得到**口径一致**的分数与评语。

调用入口：`InterviewAiFacade.judge(...)` → `chatJudge(...)`
调用时机：候选人提交答案后（含追问作答），由判题链路触发。

## 二、输入

| 参数 | 说明 |
| --- | --- |
| sessionId | 面试会话 ID，仅用于日志与追溯，不参与打分 |
| questionId | 题目 ID，用于定位被评分的题目 |
| answer | 候选人的回答正文 |
| is_follow_up | 本次是初次作答还是追问作答；追问不重复计入主线题序，但评分标准一致 |

## 三、输出契约（必须严格遵守）

**只返回 JSON，不要返回 Markdown 代码围栏，不要附加任何解释文字。**

```json
{"score":0-100,"feedback":"评语"}
```

- `score`：0-100 的数值（整数或小数均可），**必须是数值类型，不能写成字符串**。
- `feedback`：非空的中文评语。

> 后端会校验这两个字段：
> - 缺少 `score` → 判定"缺少 score 字段（0-100 的数值）"；
> - `feedback` 为空 → 判定"缺少 feedback 字段（非空评语）"；
> - 不是合法 JSON → 判定"输出不是合法 JSON"。
>
> 任一情况都会把**具体问题**回传给模型要求重新生成，最多纠正 2 次；
> 仍不满足才判定为失败。因此请一次输出正确。

## 四、评分维度与权重建议

| 维度 | 说明 | 建议权重 |
| --- | --- | --- |
| 正确性 | 结论、原理、术语是否准确，有无事实性错误 | 40% |
| 完整性 | 是否覆盖题目问到的全部要点，有无明显遗漏 | 25% |
| 深度 | 是否讲到原理、取舍、边界、故障场景，而非只背结论 | 25% |
| 表达 | 结构是否清晰、有无逻辑跳跃、能否让人听懂 | 10% |

## 五、分数段参考

| 分数 | 含义 |
| --- | --- |
| 90-100 | 准确、完整、有深度，能主动讲取舍与边界 |
| 80-89 | 正确且较完整，深度略有欠缺 |
| 60-79 | 基本正确但有遗漏或表述含糊，原理不清 |
| 40-59 | 关键概念错误或答非所问，仅有零散正确点 |
| 0-39 | 完全偏离题目，或回答为空、纯复述题干 |

> 分数段会直接影响追问策略（见 `follow-up-decision` Skill）：
> `<60` 基础追问、`60-79` 常规追问、`>=80` 深度追问。
> 因此打分要如实，不要为了"给候选人面子"抬分。

## 六、评语（feedback）写法要求

1. **先给结论**：一句话说明这个分数对应的整体判断。
2. **指出得分点**：具体说出回答里正确的部分（引用候选人的原话或关键词）。
3. **指出失分点**：说明缺什么、错在哪，而不是笼统地说"不够深入"。
4. **可改进方向**：给出 1-2 条具体建议。
5. 长度控制在 2-5 句，中文，语气专业、对事不对人。

## 七、禁止事项

- 不要因为回答很长就给高分，也不要因为回答很短就直接给低分，只看内容质量。
- 不要评价候选人的性格、学历、口音等与题目无关的维度。
- 不要在 `feedback` 里写 JSON、代码围栏或换行转义错误的字符。
- 不要输出 JSON 之外的任何字符。
